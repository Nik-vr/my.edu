# my.edu — система контроля знаний

Веб-система для школы: учитель заводит классы и предметы, собирает из заданий
работу, выдаёт её ученикам и проверяет результаты. Ученик выполняет работу по
ссылке или QR-коду и видит свой итог.

Написана на PHP без сторонних зависимостей: не требуется Composer, не нужна
сборка, не нужна система управления пакетами. Для работы нужны только PHP,
MySQL или MariaDB и веб-сервер.

Текущая версия: **0.2 beta**. Список изменений — в [changelog](changelog.md).

## Возможности

### Учитель

- **Классы и ученики.** Класс с номером и названием, список учеников, учителя
  класса, предметы. Список учеников можно загрузить файлом.
- **Работы.** Название, описание, предмет, параллель, число попыток, срок
  доступности, показывать ли результаты сразу после сдачи.
- **Задания в работе.** Шесть типов: выбор ответа, несколько ответов,
  сопоставление, упорядочивание, число, текст. У каждого задания — вес в
  баллах; у работы — сумма баллов и перевод в проценты.
- **Три способа проверки.**
  - *Тест с автопроверкой* — ученик получает отметку сразу после сдачи.
  - *Работа с проверкой учителем* — задания открыты, отметка ставится вручную.
  - *Смешанная* — часть заданий проверяется автоматически, часть ждёт учителя.
- **Итог считается по-разному:** по весам, по правилу «хотя бы одно задание
  неверно» или вообще без автоматической отметки.
- **Шкала оценок.** Свои границы, проходной балл и цвет для каждой отметки;
  отметка выводится из процента, а не считается жёстко зашитыми числами.
- **Выдача.** Отдельному ученику, целому классу или параллели; ограничение по
  числу попыток и по сроку.
- **Результаты.** По каждому ученику: баллы, процент, отметка, что уже проверено
  и что ждёт проверки учителем. Ничего не нужно «распечатывать»: результаты
  хранятся и видны в панели.
- **Перенос работ.** Экспорт и импорт архива: перенести готовую работу на другой
  сервер или в другой год.

### Ученик

- Вход по логину или адресу почты, без пароля при входе по ссылке.
- Работа открывается по персональной ссылке или QR-коду; выданная работа
  видна и в разделе «Мои работы».
- Ответы сохраняются по ходу дела: закрыл вкладку — вернулся на то же место.
- После сдачи — свой балл, процент и отметка, если учитель разрешил показ
  результатов.

### Администратор

- Учётные записи с ролями: владелец, администратор, заведующий, учитель,
  наблюдатель, ученик. У одного человека может быть несколько ролей. Набор прав
  у роли фиксирован: администратор управляет пользователями и сайтом, заведующий
  ведёт классы, предметы и сводку, учитель — свои работы, ученик — свои ответы,
  наблюдатель — только свои данные. Владелец — первый зарегистрировавшийся, он
  же администратор.
- Управление плагинами: включение и выключение для всего сайта и для
  отдельного учителя.
- Диагностика: `/health` отвечает всегда, даже когда сайт не поднимается.
- Резервная копия базы снимается сама перед любым изменением схемы.

## Требования к хостингу

- **PHP 8.1 и новее** (проверяется при старте и в панели управления). Разработка
  идёт на PHP 8.4 и новее; на хостинге достаточно 8.1.
- Расширения `pdo_mysql` и `mbstring`. `json` входит в PHP начиная с 8.0.
  Расширение `intl` не требуется: в проекте не используется.
- **MySQL 5.7+, MariaDB 10.2+ или MySQL 8.** Разработка идёт на MariaDB 10.5+.
- Любой сервер: Apache с `mod_rewrite` или nginx с `try_files`.
- Никаких дополнительных модулей не требуется. Redis, Memcached, GD, curl не
  нужны.

## Установка

### 1. Файлы

Скопируйте проект на сервер. На панели хостинга **корень сайта должен
указывать на каталог `public/`**, а не на корень проекта:

```
/home/u123456/public_html/my-edu/     ← корень проекта
└── public/                            ← это должно быть коренём сайта
    ├── index.php
    ├── .htaccess
    └── assets/
```

Остальное (`config/`, `database/`, `plugins/`, `src/`, `templates/`, `var/`)
лежит вне веб-корня и напрямую в браузер не отдаётся.

Если так настроить нельзя, добавьте в корне проекта `index.php`, который
перенаправляет всё в `public/`, и не отдавайте `public/` как отдельный сайт.

### 2. Адреса

**Apache.** Файл `public/.htaccess` уже содержит нужные правила. Убедитесь,
что Apache отдаёт `index.php` как индексный файл, а остальные адреса
перенаправляет на него.

**nginx.** Возьмите блок из
[`deploy/nginx-shared-hosting.conf.example`](deploy/nginx-shared-hosting.conf.example)
и вставьте в панель. Пример для обычного nginx (веб-сервер или VPS) —
[`deploy/nginx.conf.example`](deploy/nginx.conf.example). Правило `try_files`
обязательно: без него адреса вида `/panel/assignments/5` не найдутся.

Если адреса не переписываются, сайт всё равно работает по адресам с `/public/`
в начале: `https://edu.example.ru/public/login`.

### 3. База данных

Создайте в панели хостинга базу и пользователя с полными правами на неё.

Импортируйте `database/schema.sql` — это **снимок схемы целиком**, готовый
рабочий сервер. Импортировать можно тремя способами:

- **phpMyAdmin** — выбрать базу, «Импорт», файл `database/schema.sql`;
- **командная строка** — `mysql -u USER -p DBNAME < database/schema.sql`;
- **установщик** — `public/install.php`, см. ниже; он делает то же самое и
  сразу проверяет результат.

Отдельные миграции запускать не нужно: **сейчас файлов миграций ядра нет
вовсе**, и появятся они позже — с первым изменением схемы. Применятся они сами
при первом обращении к сайту, перед которым снимется резервная копия базы.
Отдельно запускать их не придётся.

### 4. Настройка

Скопируйте `config/config.local.example.php` в `config/config.local.php` и
заполните. Минимально нужно:

```php
return [
    'app' => [
        'url' => 'https://edu.example.ru',   // без слеша в конце
    ],
    'database' => [
        'host'     => 'localhost',
        'name'     => 'my_edu',
        'user'     => 'my_edu_user',
        'password' => 'CHANGE_ME',
    ],
    'mail' => [
        'driver'     => 'mail',              // или 'smtp'
        'from_email' => 'noreply@example.ru',
        'from_name'  => 'Школа',
    ],
];
```

Все ключи и их смысл описаны прямо в `config/config.local.example.php`.

`app.url` обязателен: по нему строятся ссылки в письмах — ссылки на
подтверждение, восстановление пароля и вход в работу.

### 5. Установщик

Откройте в браузере `https://edu.example.ru/install.php`. Он проверит
подключение к базе, импортирует `database/schema.sql` и покажет число
созданных таблиц.

**Удалите `public/install.php` сразу после установки** — установщик удаляет
себя сам, но если не смог, удалите вручную.

### 6. Письма

Письма нужны для подтверждения адреса, восстановления пароля и входа по
ссылке. До их настройки можно работать: письма складываются в
`var/log/mail-*.log`.

- `mail.driver = 'mail'` — через `mail()`;
- `mail.driver = 'smtp'` — свой сервер исходящей почты. Обычно требуется
  задать логин и пароль от ящика.

### 7. Проверка

- `https://edu.example.ru/health` — отвечает всегда и показывает версию,
  состояние базы и ошибки. Диагностика подробнее видна только с локального
  адреса сервера.
- `https://edu.example.ru/register` — регистрация. **Первый
  подтверждённый адрес становится владельцем сайта**: у него все права.

## Обновление

1. Скопируйте новые файлы поверх старых, `config/config.local.php` не
  трогайте: он не входит в обновление.
2. Откройте сайт. Если появились новые файлы в `database/migrations/`, они
   применятся сами при первом обращении, а перед этим снимётся резервная копия
   базы в `var/backup/`.
3. Следите за `var/log/schema.log` — туда пишется, что именно применилось.

Проверить состояние схемы можно и из консоли:

```
php database/migrate.php --status
```

## Локальная разработка

Нужен только PHP 8.1+ и локальный MySQL или MariaDB.

```
start-server.bat          обычный сервер на 8088
stop-server.bat
```

Тесты идут на отдельной копии базы: наборы удаляют классы и работы, а
рабочая база должна остаться целой.

```
powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1
```

Скрипт сам копирует рабочую базу в `my_edu_review_test`, поднимает тестовый
сервер на 8098 и прогоняет наборы. Полезные ключи: `-PhpPath путь\к\php.exe`,
`-TestPort 8099`, `-Only work` (один набор), `-NoSync` (не копировать базу).

Отдельные наборы запускаются напрямую, когда сервер уже поднят на 8098:

```
php tests\run_schema_tests.php             схема, без базы
php tests\run_docs_tests.php               документация говорит о проекте правду
php tests\run_ui_rules_tests.php           правила интерфейса: способы показать сообщение
php tests\run_work_tests.php               работы, попытки, выдача
php tests\run_auth_tests.php               учётные записи, письма, пароль
php tests\run_school_tests.php             классы, ученики, предметы
php tests\run_plugin_tests.php             плагины и миграции
php tests\run_grade_aggregation_tests.php  подсчёт итогов
php tests\run_transfer_tests.php           перенос работ между инсталляциями
plugins\test\tests\run_grading_tests.php   проверка заданий плагина «Тест»
plugins\variable\tests\run_variable_tests.php  проверка заданий плагина «Вариативная задача»
php tests\run_http_tests.php               маршруты и права
```

Наборов двенадцать, и порядок в `tools\run_tests.ps1` задан не произвольно:
чистящие идут раньше, сеющий — последним.

Подробности разработки — в [ПРОДОЛЖИТЬ_РАБОТУ.md](ПРОДОЛЖИТЬ_РАБОТУ.md).

## Для учителя: как этим пользоваться

Порядок обычной работы. Первый раз прочитайте целиком, дальше хватает первой
строки каждого блока.

**1. Заведите класс и учеников.** «Классы» → новый класс с номером и названием.
Дальше «Ученики» → добавить по одному или загрузить список файлом.

**2. Создайте предмет.** «Предметы» → добавить. Привяжите его к классу.

**3. Соберите работу.** «Работы» → новая работа. Укажите название, предмет,
параллель, сумму баллов, число попыток и срок доступности. Отдельно решается,
показывать ли ученику результат сразу после сдачи.

**4. Добавьте задания.** Внутри работы — «Добавить позицию». Тип задания и
способ проверки выбираются здесь же:

- **Тест** — вопросы с вариантами, автопроверка;
- **Вариативная задача** — числа в условии подставляются свои для каждого
  ученика, ответ считается автоматически;
- **Обычные типы** — выбор ответа, несколько ответов, сопоставление,
  упорядочивание, число, текст. Проверяет учитель.

У каждого задания свой вес в баллах. Сумма должна сходиться с суммой работы —
иначе при сохранении система скажет об этом и не даст выпустить работу в класс.

**5. Выдайте работу.** «Выдать» → целому классу, параллели или отдельному
ученику. Каждый получает персональную ссылку и QR-код.

**6. Проверьте.** У автопроверки результат появляется сразу, у ручной — работа
ждёт вас в «Результатах». Откройте позицию, поставьте балл, сохраните: класс
видит результат, если показ разрешён.

**7. Посмотрите сводку.** «Сводка» — по классу и предмету: средний балл,
процент выполнения, распределение отметок.

### Список учеников файлом

Формат фиксированный: **три колонки — Фамилия; Имя; Отчество**. Логины и пароли
в файле нет и не нужны: система придумывает их сама и показывает при импорте.

```csv
Фамилия;Имя;Отчество
Иванов;Иван;Иванович
Петрова;Анна;Сергеевна
```

- **Кодировка** — UTF-8. Если фамилии вышли «РџРѕРјСЂРѕРІР°», файл сохранён в
  Windows-1251: откройте его в Excel и сохраните как UTF-8.
- **Разделитель** — точка с запятой или запятая, определяется автоматически.
  Русский Excel пишет по умолчанию через точку с запятой, многие сохраняют
  через запятую. Знак с запятой внутри фамилии не встречается.
- **Первая строка** — заголовки `Фамилия;Имя;Отчество`. Они нужны, чтобы файл
  читался правильно; без них первая фамилия может уехать в заголовок.
- **Отчество можно оставить пустым**, фамилия и имя — обязательны.
- **Одна строка — один ученик.** Уже существующий ученик не создаётся заново, а
  привязывается к классу повторно.

Логины строятся из фамилии и инициала (`Иванов И.` → `И-3`), при совпадении
добавляется номер. Пароль у каждого свой, показывается один раз и больше нигде
не хранится: если он потерян, выдаётся новый. Распечатайте или передайте ученику
сразу после импорта, пока пароль на экране.

### Вход ученика по ссылке и QR

Ученику не нужен пароль, если выдать ему персональную ссылку: в ссылке стоит
токен попытки, по нему ученик попадает сразу на свою работу. QR-код учитель
распечатывает и вешает на доску — ученик наводит камеру и попадает на ту же
ссылку. Это самый быстрый способ выдать работу классу: не нужен ни список, ни
пароли.

У каждой попытки свой токен, и по нему видна ровно эта работа. Ссылка — это вход
в систему: по ней можно увидеть работу и сдать её вместо ученика. Не отправляйте
её в общий чат и не публикуйте QR там, где его увидят посторонние. Если ссылка
попала к постороннему, проще всего выдать работу заново — тогда у ученика будет
новая попытка со своим токеном.

## Персональные данные учеников

Сайт хранит фамилии, имена, классы, ответы на задания и отметки. Часть этих
сведений прямо относится к детям, и в России их обработка без законного
основания ограничена (152-ФЗ). Коротко о практических последствиях:

- **Ученик — ребёнок, а не сотрудник.** На него не распространяются трудовые
  договоры и согласия на обработку. Основание обычно даёт школа как
  образовательная организация, а не учитель как частное лицо.
- **Пароли не хранятся открытым.** Ученик входит по одноразовой ссылке или по
  логину, который вы задали; пароль система не хранит открытым и не может его
  показать — при утерянном пароле выдаётся новый.
- **Учётная запись и попытки удаляются вместе.** Ученика убирают из класса, и
  его попытки снимаются со всех классов сразу; если он не числится больше ни в
  одном классе, удаляется и сама запись. Восстановить это из интерфейса нельзя,
  поэтому решение принимается до нажатия, а не после.
- **Кто видит результаты.** Ученик видит только свои. Учитель — работы своего
  класса. Заведующий и администратор видят сводку. Права задаются ролями и не
  расширяются «по умолчанию».
- **Копия базы содержит всё.** Дамп в `var/backup/` — это персональные данные
  целиком: держите `var/` вне публичной части и следите за тем, кому отдаёте
  копии.
- **Срок хранения.** Закон не требует хранить результаты вечно: по окончании
  учебного года их можно удалить, и понадобится согласие школы или решение
  о сроке хранения. Копию базы после этого тоже стоит снять заново.

Конкретные сроки и форму основания — вопрос к школе и к локальным актам, а не
к настройке программы. Программа не отправляет данные третьим лицам: почта
уходит через ваш сервер, аналитика и сторонние счётчики не подключены.

## Для разработчика

### Пример плагина целиком

Рабочий образец лежит рядом — [plugins/test](plugins/test). В нём всё, о чём
ниже, и он проверяется наборами. Сво��ой плагин делается копированием этой папки:
`plugin.json`, точка входа в `src/`, каталог `migrations/`.

`plugins/test/plugin.json`:

```json
{
  "id": "test",
  "name": "Тест с вопросами",
  "version": "1.0.0"
}
```

Точка входа `plugins/test/src/TestPlugin.php` начинается так:

```php
<?php

declare(strict_types=1);

namespace MyEduPlugin\Test;

use MyEdu\Plugin\AssessmentPlugin;
use MyEdu\Plugin\PluginMigrationRunner;
use MyEdu\Plugin\PluginServices;
use RuntimeException;

final class TestPlugin implements AssessmentPlugin
{
    public function __construct(private readonly PluginServices $services) {}

    public function id(): string
    {
        return $this->services->manifest()?->id ?? 'test';
    }

    public function name(): string
    {
        return $this->services->manifest()?->name ?? 'Тест с вопросами';
    }

    public function version(): string
    {
        return $this->services->manifest()?->version ?? '1.0.0';
    }

    public function install(): void
    {
        $dir = $this->services->ownPlugin('test')->migrationsDir();

        if ($dir === null) {
            throw new RuntimeException('Каталог плагина не найден на диске — миграции применить некуда');
        }

        (new PluginMigrationRunner(
            $this->services->database(),
            'test',
            $dir,
            $this->services->dump()
        ))->apply();
    }

    // ... остальные методы контракта
}
```

Плагин подхватится сам при следующем запросе: каталог сканируется, страница
`/panel/plugins` покажет его как «не установлен», включение применит миграции
из `plugins/test/migrations/`. Контракт — 22 обязательных метода; таблица с
каждым — в [plugins/README.md](plugins/README.md).

Три вещи, которые чаще всего делают неправильно:

- **Написать `id`, `name` и `version` в классе.** Плагин со временем назовёт
  себя не той версией, что стоит в `plugin.json`. Берите их из
  `$services->manifest()`.
- **Считать каталог миграций из `id`.** Папку плагина переименовывают при
  копировании заготовки, и `id` при этом прежний — миграции уедут в
  несуществующий каталог, а плагин молча отметится установленным. Берите
  `ownPlugin('test')->migrationsDir()`.
- **Проверять CSRF в `saveAnswer()`.** Это уже делает ядро. Плагин отвечает за
  формат и допустимые значения своего ответа.

### Переменные окружения

| Переменная | Где нужна | Что делает |
|---|---|---|
| `MYEDU_DB_NAME` | скрипты, наборы | имя базы вместо взятого из конфигурации. Наборы запускают на `my_edu_review_test` — рабочая база подменяется только здесь |
| `MYEDU_ALLOW_DESTRUCTIVE` | `install_test_db.php`, `sync_test_db.php`, `seed_demo_test.php` | разрешает пересоздание базы, в имени которой нет слова `test`. Без него скрипт отказывается работать |
| `MYEDU_SKIP_BACKUP` | `migrate.php` | пропустить копию базы перед миграцией осознанно. То же, что ключ `--skip-backup` |
| `MYSQLDUMP` | копирование базы | путь к `mariadb-dump` или `mysqldump`, если он не в `PATH` |
| `MYEDU_CREATE_PASSWORD` | `create_user.php` | пароль нового пользователя, если он не подаётся со стандартного ввода |

Значение `MYEDU_ALLOW_DESTRUCTIVE=1` ставится осознанно и руками: это
единственный способ обойти защиту, которая специально мешает стереть рабочую
базу.

## Способы проверки (плагины)

Способ проверки знаний — подключаемый плагин. Ядро о нём ничего не знает:
добавить новый способ, не трогая ядро, — и есть смысл всей конструкции.

В поставке два:

- **Тест** — задания с вариантами, автопроверка, два способа подсчёта итога;
- **Вариативная задача** — числа в условии подставляются свои для каждого
  ученика, ответ считается автоматически.

Включаются в разделе «Плагины» панели: можно выключить плагин целиком на
сайте или только у отдельного учителя. Устройство плагинов и порядок написания
своего — в [plugins/README.md](plugins/README.md).

## Перенос работ между инсталляциями

Работы, задания и результаты можно выгрузить в архив и загрузить на другой
сервер. Формат архива версионируется, поэтому старый архив не сломает новую
версию и наоборот.

## Резервные копии

Перед любым изменением схемы снимается полный дамп базы в `var/backup/`. Если
утилиты `mariadb-dump` на сервере нет, копия снимается средствами PHP и
получается обычным SQL-файлом, который восстанавливается через phpMyAdmin.

Что происходит, если копия не снялась, зависит от ключа
`security.backup_before_migrations_blocking`:

- **`true` (по умолчанию) — миграция не применяется.** Схема остаётся прежней,
  сайт продолжает работать, причина написана в `var/log/schema_failure.json` и
  в `var/log/schema.log`. Повторные попытки ничего не делают, пока файл
  отслеживания не уберут руками: иначе сломанная миграция повторялась бы при
  каждом заходе на сайт. Это поведение выбрано потому, что `DROP TABLE` в
  MySQL не откатывается — без точки отката сбойная миграция оставляет базу в
  промежуточном состоянии, из которого её не выбрать.
- **`false` — миграция применяется без точки отката.** Так делают, когда копии
  снимает сам хостинг по расписанию и своей точки отката у проекта не будет.
  Значение меняется только в `config/config.php`.

Одна копия — это не страховка от ошибок в самой миграции: дамп снимается перед
изменением, а не после. Свои копии файлов проекта делайте по расписанию
хостинга — они не входят в состав программы.

### Восстановление из копии

1. Откройте `var/backup/` и выберите последнюю копию, снятую **до** проблемы.
2. Импортируйте её через phpMyAdmin («Импорт») или командой строкой:
   `mysql -u USER -p DBNAME < var/backup/имя-файла.sql`.
3. На хостинге, где папки `var/` нет, файлы проекта заменяются на новые, а
   база возвращается копией. Порядок именно такой: файлы вперёд, база вторым
   шагом, иначе старый код встретит новую схему.

## Если что-то не работает

- **`/health`** — всегда отвечает и показывает, что сломалось. Начните с него.
- **`var/log/`** — журналы: `schema.log` (что делалось со схемой),
  `mail-*.log` (письма), `backup-*.log` (копии базы), `app-ГГГГ-ММ-ДД.log`
  (события сайта).
- **Вход не работает, а `/health` отвечает** — загрузите `public/check_login.php`
  и откройте его, передав ключ диагностики: `check_login.php?key=…`. Без
  правильного ключа страница отвечает 403 и ничего не проверяет. Ключ задаётся
  в `config/config.local.php` (`diagnostics.key`), а после диагностики файл
  следует удалить. Страница ничего не меняет: только читает.
- **Белый экран** — почти всегда это `display_errors = off`. Смотреть надо в
  журнал `var/log/app-ГГГГ-ММ-ДД.log`: он пишется всегда. Включать
  `app.debug = true` на боевом сервере не нужно — режим выводит в страницу
  внутренние пути и тексты ошибок, и это видно посетителю. Включайте его только
  во временной копии `config.local.php` на своей машине.
