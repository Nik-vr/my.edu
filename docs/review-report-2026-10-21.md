## ЧАСТЬ 1. ОБЩАЯ ОЦЕНКА

Проект представляет собой систему контроля знаний на собственном PHP-фреймворке без внешних зависимостей. Архитектура продумана: front-controller, DI-контейнер, модульные контроллеры, плагинная система с контрактным интерфейсом (22 метода), разделение прав доступа на уровне роутера.

**Общая оценка архитектуры: хорошо.** Код последователен, разделение ответственности ясно.

## ЧАСТЬ 2. СОХРАННОСТЬ ДАННЫХ ПОЛЬЗОВАТЕЛЕЙ

### 2.1. Механизм old-данных

**Реализован корректно.** Два механизма:
- **Автоматический** (`keepInput()`) — сохраняет все POST-параметры в сессию, исключая пароли и токены. Используется в `AssignmentController`, `IssueController`, `OtpImportController`, `SubjectController`.
- **Ручной** — данные сохраняются отдельно в сессию (`class_edit_old`, `student_add_old`, `profile_old` и т.д.).

Все шаблоны корректно используют `??` fallback для восстановления:
```php
value="<?= $view->e($old['name'] ?? $class['name']) ?>"
```

**Вердикт: OK.** Конфликтов имён нет, данные читаются через `pull()` (одноразово), flash-сообщения отделены от old-данных.

### 2.2. Черновики (task-draft.js)

**Реализовано качественно.** Серверные черновики для редактора заданий: debounce 700мс, `sendBeacon` при уходе со страницы, автоматическое восстановление при повторном открытии. Файлы намеренно исключены (ограничение браузера).

**Вердикт: OK.**

### 2.3. File uploads

**Реализовано корректно.** Файлы не могут быть восстановлены при ошибке — это ограничение браузера, а не баг. Старые файлы (аватары) не теряются, так как хранятся в БД/на диске.

**Вердикт: OK.**

### 2.4. Динамические поля

`Ui::optionRows()` принимает массив значений из `$old`. JS-добавление/удаление строк — клиентское, при POST данные уходят целиком через `keepInput()`.

**Вердикт: OK.**

### 3.2. Найденные проблемы

|---|------|-------------|----------|
| A | `assignment-items.js` (открытие редактора, ~строка 514) | **Средний** | Не проверяет 401/403/419 и `response.redirected`. При истёкшей сессии сервер перенаправляет на страницу входа (HTML), `response.json()` выбрасывает исключение. Пользователь видит «случайную перезагрузку» без объяснения. |
| B | `work-list.js` (удаление работы, ~строка 89) | **Средний** | Не проверяет 401/403/419 и `response.redirected`. При истёкшей сессии ошибка интерпретируется как «Связь с сервером прервалась» — вводит в заблуждение (сеть не при чём). |
| C | `task-draft.js` (запрос черновика, ~строка 501) | **Низкий** | Не проверяет статус-код. При 401 ошибка молча проглатывается. Для авто-сохранения допустимо, но в логах dev-сервера создаётся шум. |
