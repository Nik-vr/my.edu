# План устранения по результатам ревью 18.10.2026

Источник: `docs/ревью-2026-10-18.md`. План составлен после того, как критичные
пункты отчёта были сверены с кодом — отмеченные строкой «проверено» подтвердились,
два пункта требуют уточнения, один к моменту составления плана уже закрыт.

Каждый шаг обязан приносить проверку: тест, браузерную пробу или проверку
скриптом. Шаг без проверки считается невыполненным, даже если код выглядит
правильно — именно на этом проекте уже дважды находилось расхождение между тем,
что написано, и тем, как оно работает.

---

## 0. Главное решение: публиковать сейчас или после

Репозиторий создан, коммит и тег `0.2-beta` лежат **локально**, на GitHub ничего
не отправлено. Это позволяет исправить критичное до первой публикации, не
плодя версии.

**Рекомендация: не отправлять до выполнения волны 0.** Тогда первая публичная
версия остаётся `0.2 beta` — «первая публичная версия», один раздел в changelog,
и в публичный репозиторий не уедут ни открытый `check_login.php`, ни ложные
утверждения в документах, ни путь с именем пользователя.

Если владелец решит отправить сейчас, то волна 0 — это уже не правки, а
изменение логики, и по правилам версий следующая версия будет `0.3`.

## 1. Волна 0 — до первой публикации

Критичное и то, что делает публичный репозиторий недостоверным.

### 0.1 Диагностическая страница без настоящего ключа (K1) — проверено

`public/check_login.php:40` проверяет только наличие `?key=`; значение не
сверяется. Скрипт показывает состояние учётной записи по адресу, запускает
миграции, снимает копию базы и умеет отправлять письма. Любой, кто угадает
`?key=1`, получает это.

Что сделать — по выбору владельца, но выбрать одно:

- **вариант А (рекомендуется для релиза):** убрать файл из поставки. Диагностика
  живёт в `check_login.php` только на боевом сервере и кладётся вручную;
- **вариант Б:** сравнивать ключ через `hash_equals` с секретом из
  `config/config.local.php`, убрать из GET-обработчиков запуск миграций, снятие
  копии и отправку писем, ограничить вывод состоянием базы без данных учётных
  записей.

Проверка: запрос без `?key=` и с чужим `?key=` даёт 403; запрос с верным ключом в
`config.local.php` открывает страницу. Добавить в `tests/run_http_tests.php`.

### 0.2 Установщик открыт и раскрывает детали (K4) — проверено

`public/install.php`: доступен любому, пока его не удалили; показывает число
таблиц (`SHOW TABLES`, строки 192 и 253) и текст ошибок PDO (`getMessage()`,
строки 183 и 234); первый зарегистрировавшийся становится владельцем.

Что сделать:

1. требовать ключ установки — тот же механизм, что и в 0.1, отдельная настройка
   `install.key`;
2. при `app.debug = false` не выводить текст ошибки PDO, а писать её в журнал;
3. убрать `SHOW TABLES` из отчёта, оставить только «схема применена»;
4. требовать, чтобы база была пустой, и писать об этом прямо (сейчас проверка
   есть, но отчёт показывает состояние).

Проверка: `tests/run_http_tests.php` — без ключа 403, с чужим ключом 403, с
верным ключом импорт на пустой базе; в ответе нет ни имени таблицы, ни текста
ошибки PDO.

### 0.3 Письма по умолчанию пишутся в файл (K5) — проверено

`config/config.php:88` — `mail.driver = 'log'`. Токены подтверждения адреса и
сброса пароля оказываются в `var/log/mail-*.log` открытым текстом.

Что сделать:

1. поменять умолчание на `mail`;
2. маскировать токены в журнале: в `log`-драйвере показывать только первые 6
   символов и длину, остальное — `***`.

Проверка: тест письма проверяет, что в `mail-*.log` нет полного токена; отдельная
проверка, что при `driver = 'log'` токен в журнале обрезан.

### 0.4 Снимок схемы стирает данные при импорте в рабочую базу (K3) — проверено

`database/schema.sql` содержит 14 строк `DROP TABLE IF EXISTS`, включая
`users` (строка 66) и `schema_migrations` (строка 564). Импорт этого файла в
рабочую базу удаляет всё.

Что сделать: перейти на `CREATE TABLE IF NOT EXISTS` без `DROP`, а в шапку файла
добавить явное предупреждение: «файл предназначен для ПУСТОЙ базы; в базу с
данными он не импортируется».

Проверка: `tests/run_schema_tests.php` — в файле нет `DROP TABLE`; `install_test_db.php`
и `install.php` продолжают собирать базу (там импорт идёт в пустую базу).

### 0.5 Пароли учеников лежат в сессии открытым текстом (K2) — проверено

Что сделать: показывать пароль один раз, из ответа страницы, и не хранить в

Проверка: тест — после страницы выдачи в сессии нет `issued_credentials`; пароль

### Что стоило дороже всего

  По коду наоборот: попытки снимаются со всех классов сразу, а запись удаляется
